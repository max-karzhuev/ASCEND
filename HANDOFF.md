# ASCEND project handoff

ASCEND 2.0 (build 12) is a local-first SwiftUI app for macOS 14+ and iOS 17+. The repository contains the native app, Mac widget extension, dependency-free Swift core, and optional personal Node gateway. The app opens in local mode. Signing for a physical iPhone, private iCloud sync, and public Mac distribution each have their own setup in the [installation guide](Docs/SETUP.md).

## Run a fresh checkout

Open `ASCEND.xcodeproj`, choose the **ASCEND** scheme and **My Mac**, then run. The local Mac and simulator builds require Xcode with the macOS 15+ SDK for the widget image APIs and the iOS 17+ SDK. Use Node 22+ for the gateway. The local build does not require a development team or provider key.

```sh
swift test
(cd Gateway && node --test)
./Scripts/build-local.sh
open build/mac/Build/Products/Release/ASCEND.app
```

For iPhone Simulator, select an installed iPhone simulator in Xcode or use the simulator build command in the [README](README.md). Run `python3 Scripts/generate_project.py` after adding Swift source files, and commit the generated project. The generator owns build settings and target membership. Apply project-wide configuration changes there too.

Version 2.0 recalculates achievement and quitting streaks from activity with an automatic two-missed-day freeze. Rules live in `StreakRules`, `Quitting`, and `Progression.streakStatus`. Shared button sizing lives in App/Design.swift. Quest completion covers the checkbox, title and whitespace up to the separate options menu.

## Home widgets, quitting, gym and Health (2.0)

Home → **Customize** shows every card. Move with the arrows or drag the native list rows, hide/add cards, choose standard/full width, or restore defaults. Cards fill the next available top edge in two columns, eliminating tall empty rows; full-width cards start a new row. Narrow screens use your saved single-column order. Layout is local SwiftData metadata (`homeLayout`); hiding a card never deletes its records. The card context menus provide the same controls. All new action targets are at least 44 points.

`Sources/AscendCore/HomeWellness.swift` contains the widget layout, freeze reducer, quitting/workout models, weekly muscle counts and sleep interval union. The new screens are `App/HomeCustomization.swift`, `QuittingView.swift`, `GymView.swift`, `MuscleMap.swift` and `HealthView.swift`. `DashboardLayout.swift` packs the cards; `AnatomyPaths.swift` contains normalized, preconverted anatomical curves. `AppStore` saves quitting goals/check-ins, workout plans/logs and gym targets in the existing operation ledger. Upgrade all sync participants to 2.0 before exchanging these new entity kinds.

A streak counts successful activity/check-in days, never frozen days. After activity on Monday, Tuesday and Wednesday may be missed; returning by Thursday night preserves the count and adds Thursday. Returning Friday starts a new streak. The first uncompleted day stays open; the card shows a frozen state once a missed day has ended. Unlike 1.9, indefinitely empty rest days no longer protect an achievement streak. Quest completions newly made on an overdue quest credit their actual completion date; the frozen calendar plan still shows that occurrence as completed. Undo/re-complete preserves the original credit date/reward. Brain sessions, drills and goal progress retain their existing achievement credit.

Quitting supports Weed, Alcohol, Smoking, Drugs and custom goals. Each goal has an evening check-in opening hour (6–11 PM, default 8 PM) in the planning timezone. Only today's check-in is editable; successful check-ins prolong the streak, a setback explicitly resets it, and skipped days may use the same automatic freeze. Check-in IDs are stable per goal/day. A goal can be archived/restored or deleted. The manager shows the last seven check-ins. Reminders use the app's existing selected notification device and never expose the goal name in the notification body.

The Gym screen has a Monday-to-Sunday plan. Choose a day and create its workout; separate workouts can use different days. Each plan contains named exercises, sets, a custom reps/minutes/distance prescription, required muscle selections per exercise and scheduled weekdays. Saving a plan creates a matching quest on each scheduled day and keeps its exercises and muscle groups in the quest. Existing plans are linked to quests as the app reconciles its ledger. Logging every planned exercise completes that day's workout quest; a partial log counts actual training toward muscle progress but leaves the quest open. Removing the log reverses an automatic quest completion when no matching full log remains. Editing a plan updates today's open workout and future days; logged workout and completed-quest snapshots retain their history. The black anatomical front/back schematic (MIT-licensed geometry, see Configuration/AnatomyLicense.txt) highlights muscles scheduled for today in the profile's accent; progress fill represents logged sessions for the current Monday-based planning week. All 14 requested groups are selectable, with Cardio in the labelled muscle selector. The default goal is three sessions per muscle per week; each target can be set independently from 1–14. Logging confirms completed exercises and stores a snapshot, so later plan edits/deletion cannot rewrite history. Each workout counts once per muscle; removing a log reverses its progress. These are tracking goals, not strength estimates or exercise prescriptions.

Apple Health is read-only on supported iPhone/iPad devices: daily steps, active energy, walking/running distance, and asleep time during the last 24 hours. Sleep excludes awake/in-bed-only records and unions overlapping asleep intervals. Connection asks for granular permissions; missing/denied data displays a dash, never a fabricated zero or a claim that read permission was granted. Users can hide metrics, refresh and disconnect. Raw Health values live only in memory, never in chat, JSON exports or ASCEND CloudKit records. Local connection/visibility preferences persist. Foreground activation and a five-minute foreground refresh update readings. Apple Watch and compatible trackers feed Apple's Health store; no direct Watch pairing or watchOS app is required. Mac shows setup instructions because HealthKit readings are unavailable there. HealthKit capability and the read-purpose string are included for iOS; physical-device entitlement/provisioning and live Watch data require the owner's device and Apple team.

## Puzzle requests and storage

Connecting a model enables a daily set for the active subject. Opening or choosing a topic can use one generation request. The loader reuses a saved set for the same planning day, subject, provider and model. Overlapping requests from the same store share an in-flight check. Each device can generate its own set before CloudKit exchanges complete. General puzzles run offline. When generation fails, the feed offers retry and keeps a saved set or the general collection playable.

The gateway receives the chosen subject and learning settings. Generated questions, worked solutions and submitted attempts enter the same local history, export and optional private sync as other Brainmaxing sessions. Chat uses a separate in-memory conversation. The provider keys belong on the gateway. The native app stores only the gateway token in Keychain. For deployment, configuration and usage controls, see the [gateway guide](Gateway/README.md).

## Mental math

Home and the Mac Puzzles screen offer **Start drill** and a settings button. The default is a two-minute mix of addition, subtraction, multiplication and division. The card and setup screen offer Easy, Medium and Hard operand presets. The previous default ranges are Medium. Hand-edited ranges remain available as Custom. Changing difficulty preserves operations and duration. Players can select a duration from five seconds to ten minutes, choose operations, and edit each operand’s inclusive range. Subtraction reverses a sum and division reverses a product. Entering the complete answer scores a point and clears the field for the next question. The deadline continues across app backgrounding. Ending early shows the current score. Only a timed finish replaces the last completed score.

The drill runs offline. `AppStore` saves its settings and last completed score in the device’s SwiftData metadata under `mentalMath`. Clearing local data removes them. An active round lives in memory. Starting in 1.8, a timed finish also writes a dated mentalMathRound operation to the activity ledger. Each distinct round ID earns 5 XP at every score and difficulty. The local result and ledger operation commit together. Rounds count toward daily and lifetime XP and travel with JSON exports and optional private sync. A manually stopped round earns no XP. Upgrade participating devices to 1.8 before exchanging new round records with iCloud. Version 1.7 kept only the last score locally, so older scores have no retrospective XP.

## GitHub and distribution

- The workflow in `.github/workflows/test.yml` runs on pushes and pull requests. It checks project regeneration, runs the Swift and Node suites, compiles the Mac app with its widgets, verifies the bundle signature, checks app and widget version agreement (including the version on a release tag), and compiles the iPhone simulator app. It uses read-only repository permissions.
- Local copies of the runnable app and the two ZIP files live in the ignored `Downloads/` directory of the delivery repository. A fresh checkout builds its own app. Use a tagged source archive for source distribution.
- The local Mac package is ad hoc signed. For a public Mac download, sign the app and extension with the project's Developer ID identity, notarize and staple the app, then verify the extracted release ZIP on a separate Mac. Attach that ZIP to the GitHub Release for the matching source tag.
- The repository owner still needs to choose the GitHub destination and visibility. If releasing under an open-source license, choose the intended license before inviting reuse. The repository currently contains no license grant.
- For App Store or iCloud distribution, configure the owner's bundle identifiers, team, App Group and CloudKit container, then verify physical-device signing and production sync. Replace the example identifiers in the project generator and configuration as described in the installation guide.

For a quick manual pass, open General, choose the second question, request a hint, submit an answer and revisit it from Brainmaxing. With a configured gateway, select a custom subject, reopen Home and verify the same set returns. Send a draft from the home chat and open the expanded conversation. Check the compact and full calendars after completing a scheduled quest. For mental math, choose a five-second addition drill with both ranges fixed at 2. Type 4 twice, let the timer expire and verify that Home reports two correct and the player gains 5 XP. Start again and end early to confirm the last completed score is preserved.
